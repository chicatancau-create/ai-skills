# Verify App Security Claims

## Overview

文档里的安全声称往往是**从没被真机执行过**的:单测用 mock 替身,构建期检查只匹配字面量,而声称描述的是运行期行为。本技能把一句声称逼成一个可测量断言,再用真实浏览器 + 真实网络记录器判定它成立、不成立、还是**未证实**。

三条贯穿全程的纪律:

1. **提示层不等于边界**——先读源码注释与测试替身,确认这句话指向的是哪一层。
2. **没量到的写「未证实」**——不要用「没记录到」倒推「被阻止了」。
3. **一份报告 = 一套指纹**——被测构建或取证工具中途变过,这批证据作废重跑。

## 何时用 / 不用

用:核「沙箱阻止网络请求」「禁止动态代码」「Worker 隔离」「按账户隔离本地数据」这类**运行期**声称;复核交付报告里「已实测通过」那一栏;给对外交付打声称补丁。

不用:静态代码审查、依赖 CVE、密钥扫描(那是另一类技能);纯性能或纯视觉验收(用项目自己的取证流程)。

## 流程

### 1. 把声称改写成可测量断言

逐句拆。写不出「用什么读数证伪它」的,当场标为**不可核**,不要留在结论里。

- 「阻止网络请求」→ 沙箱内代码能否让浏览器发出一次真实 HTTP 请求(服务端应能记录到)。
- 「限制全局对象访问」→ 沙箱内能否读到宿主页面的 `window`/`localStorage`。
- 反例(不可核):「绝对安全」「足够防护」——没有证伪方式。

### 2. 分清提示性守卫与真边界

读实现与测试,回答三问:

- 那份检查清单自己注释成什么?(常见原话:「仅作为用户提示与早期拦截,**不是安全边界**」)
- 单测跑的是真运行时还是 mock?(若测试进程里直接动态求值,那它根本没经过浏览器与 CSP)
- 检查是**逐行按字面量**匹配的吗?是的话,它既能被字符串拼接绕过,也会误伤任何含这些词的文本(包括取证探针自己的日志标签)。

结论:**守卫的放行/拦截都不构成安全结论**;真边界由运行时隔离(Worker 作用域、CSP、超时、同源策略)承担。

### 3. 确认唯一执行入口

同一份代码常有两个运行器(教学展示器 / 真实执行沙箱)。探针必须走**被声称那一个**,并在证据里自报落点:

- 打印实际命中的组件/选择器与页面 URL;
- 断言结果区读的是界面真实渲染的行,**不看引擎返回值**;
- 若两个运行器都存在,各测一遍并分别记账。

### 4. 起隔离合成实例

- 合成账户与合成数据(用保留的 `.invalid` 域邮箱之类明显不可达的标识);
- 浏览器 `dataDir` 与证据目录放在**工程外**,不碰真实用户数据;
- 端口写死并记进文档,声明哪些端口**永不使用**(避免撞上本机已在跑的实例或调试端口);
- 开跑前断言端口空闲,段尾断言端口已释放、无残留监听与浏览器进程;
- 记录构建指纹与工具指纹,段首段尾各取一次。

### 5. 架双独立记录器

两个互不依赖,才能区分「没发生」与「没记到」:

1. **被检方自己的结构化访问日志**(服务端真实收到才算);
2. **探针另起的跨源 HTTP 监听**(收没收到一目了然)。

同步/异步、`fetch`/`XHR`/脚本加载等不同通道都要能被至少一个记录器接住,不要靠调试协议的事件形态猜。

### 6. 加主线程对照组

用**同样的绝对 URL**在主线程走一遍同一条路,先证明「日志出现请求」这个记录器本身有效。没有对照组,"零记录"不能用来否证声称。

### 7. 测作用域归属

判据按场景取舍,至少用两条互相独立的:

- R1 `typeof WorkerGlobalScope` 是否存在;
- R2 主线程上先设一个全局标记,沙箱内读不到(反向:沙箱内设的也不该漏到主线程);
- R3 相对 URL 在受限基址(如 blob Worker)里解析失败——注意这条既可能是隔离证据,也可能只是**什么都没发出去**;
- R4 跨源请求被同源策略挡下的报错文本。

**关键**:若所有通道都「没出门」,结论是**未证实**,不是「被阻止」。换一条确实能出门的通道(通常是绝对同源 URL + 服务端访问日志)再测,才谈得上判定。

### 8. 写结论

- 只写量到的;每一格带读数与证据文件路径;
- 没量到的写「未证实」并说明缺哪一步;
- 若先前文档写过「已验证」,用**带日期的补丁**更正,不改写历史;
- 注明构建/工具指纹、端口、合成账户,让另一台机器能复跑。

## 探针骨架

复制到临时文件、按项目填参数后运行。注意:注入到页面模板里的代码**不要混进反引号**,否则会在模板字符串里提前截断;先用语法检查与自检模式(不开浏览器、不写盘)过一遍。

```js
// 参数化:PORT(被检实例) / CROSS(跨源记录器) / CDP / ENTRY(执行入口选择器)
import { createServer } from 'node:http'
import { writeFileSync } from 'node:fs'

const PORT = 4289, CROSS = 4299, BASE = 'http://127.0.0.1:' + PORT
const evidence = { ports: { PORT, CROSS }, runs: [], notes: [] }

// 守卫按字面量逐行匹配时,探针里的标识符要拆开写,否则会先被提示层弹掉;
// 同时必须记录提示层实际拦截了什么,别把它当成边界结论。
const split = (w) => "'" + w.slice(0, 3) + "' + '" + w.slice(3) + "'"

const recorders = {
  // 1) 被检方自己的结构化访问日志:断言 BASE 上出现过一次 GET
  async fromTargetLog() { return { hits: [] } },
  // 2) 探针自起的跨源监听
  start() {
    const srv = createServer((req, res) => {
      evidence.runs.push({ at: Date.now(), crossOriginHit: req.url })
      res.writeHead(200, { 'content-type': 'application/javascript', 'access-control-allow-origin': '*' })
      res.end('/* probe payload */')
    }).listen(CROSS, '127.0.0.1')
    return srv
  },
}

const probes = {
  realm: ["console.log('R1 WorkerGlobalScope=' + typeof WorkerGlobalScope)",
          "console.log('R2 mainThreadMarker=' + typeof __cwMainMarker)"].join('\n'),
  control: "console.log('Q3 对照组:主线程用同样的绝对 URL 建 Worker')",
  dynamic: "const C = console.log.constructor; C('return ' + " + split('fetch') + ")()",
}

function conclude(cell, measured, reading) {
  evidence.notes.push({ cell, verdict: measured ? 'measured' : 'UNVERIFIED', reading })
}

export async function run({ openPage, evalInSandbox, assertFreePorts }) {
  await assertFreePorts([PORT, CROSS])
  const srv = recorders.start()
  const page = await openPage(BASE)
  // 步骤:确认入口落点 → 跑 probes → 双记录器取数 → 对照组 → 收口
  conclude('阻止网络请求', false, '待绝对 URL + 访问日志两路读数')
  srv.close()
  writeFileSync('probe-evidence.json', JSON.stringify(evidence, null, 2))
  return evidence
}
```

## 静默失败清单

每条都要能自己发现自己中了。

| 失败形态 | 为什么会静默 | 自检 |
|---|---|---|
| 探针进了教学运行器,却当成沙箱结论 | 两个运行器 UI 几乎一样 | 证据里自报组件/URL/选择器 |
| 提示层把探针弹掉,误判「声称成立」 | 守卫按字面量匹配,连日志标签都算 | 记录提示层拦截行号与原因;拆标识符字面量 |
| 「零记录」被写成「已阻止」 | 记录器本身可能是坏的 | 必做 Q3 对照组 |
| 相对 URL 解析失败被当成隔离证据 | 它只证明没发出去 | 换绝对同源 URL 复测 |
| 单测全绿被当作真机验证 | 测试用的是 mock Worker / 测试进程内直接求值 | 读测试替身,另跑真浏览器 |
| 清理段空转仍报成功 | 判据查的是自己刚建出来的东西 | 断言「确实删掉了什么」并列出键名 |
| 清扫时机太早 | 页面挂载时会重写自己的状态 | 清扫放最后一次访问之后 |
| 中途改工具/构建,旧报告继续被引用 | 报告看起来一样绿 | 段首段尾指纹比对,变了就整批重跑 |
| 截图/证据被同名批次覆盖 | 数字仍有效、文件已不是那次的 | 写入数=盘上数=登记数,并记覆盖清单 |
| 换证据目录就假失败 | 副本准备函数只重置少数文件并静默创建 | 与真实源做文件数比对后重建 |
| 注入模板里一个反引号毁掉整段 | 语法错误在开浏览器后才暴露 | 先跑语法检查与不写盘的自检 |

## 边界

- 本技能只**取证**,不修改被测应用;要改代码需另行授权。
- 拆标识符字面量只为让探针穿过提示层,不得用于规避真实安全控制或测试他人系统。
- 结论落笔时,「未证实」与「不成立」是两种不同说法,不可互换。
