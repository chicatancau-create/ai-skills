# 安全审查与加固 (fs-security)

## 审查方式

1. 对照当前 OWASP 官方应用安全清单逐项核对代码，并记录使用的版本/发布日期
2. 运行 `npm audit`(或 `pnpm audit`)检查依赖漏洞, 高危必须升级
3. 扫描仓库历史与当前文件, 确认无密钥泄露(正则搜 API key/私钥格式/password 字样)
4. 输出审查报告: 每项 = 通过/风险/不适用 + 证据

## OWASP 核对清单

### A01 访问控制缺失
- [ ] 每个接口/Server Action 独立校验权限(不依赖前端隐藏按钮)
- [ ] 资源所有权校验(用户只能操作自己的数据)
- [ ] 管理端接口与普通接口分离并单独授权
- [ ] 默认拒绝: 未匹配规则一律 403

### A02 加密失效
- [ ] 密码用 argon2id/bcrypt(带盐), 绝不明文/自制哈希
- [ ] 全站 HTTPS(生产强制, HSTS)
- [ ] 敏感数据存储加密; 传输 TLS 1.2+
- [ ] 无硬编码密钥/证书

### A03 注入
- [ ] SQL: 全部参数化查询/ORM(严禁字符串拼接 SQL)
- [ ] NoSQL/命令/LDAP 注入同类检查
- [ ] 动态排序字段/表名走白名单
- [ ] 正则防 ReDoS(禁用超时上限)

### A04 不安全设计
- [ ] 关键流程有速率限制(登录/注册/找回/验证码)
- [ ] 批量操作防滥用(单次请求数量上限)
- [ ] 幂等键防重复提交(支付/下单)

### A05 安全配置错误
- [ ] 生产关闭调试信息/详细错误栈(只回 requestId)
- [ ] 安全响应头: CSP、X-Content-Type-Options、X-Frame-Options、Referrer-Policy
- [ ] CORS 白名单明确, 不与凭证 `*` 同开
- [ ] 依赖锁定文件提交, 定期升级

### A06 易受攻击的组件
- [ ] `npm audit` 无高危; 及时跟进框架安全公告
- [ ] 组件选型考虑维护活跃度

### A07 身份验证失效
- [ ] 会话 cookie: httpOnly + Secure + SameSite=Lax/Strict
- [ ] JWT 设过期时间, 密钥强度足够且管理规范
- [ ] 登录防暴力破解(限流+锁定+验证码)
- [ ] 密码重置用一次性短时效 token

### A08 数据完整性失效
- [ ] 不信任客户端传入的价格/权限/角色字段(服务端重算)
- [ ] 签名校验外部回调(Webhook)

### A09 日志与监控失效
- [ ] 登录/权限变更/敏感操作有审计日志
- [ ] 日志不含密码/token/完整银行卡号
- [ ] 异常有告警渠道

### A10 SSRF
- [ ] 用户可控 URL(回源地址/图片拉取/webhook)校验协议与目标(禁内网 IP 段)
- [ ] 服务端请求外发统一出口校验

## XSS 与 CSRF 专项(Web)

- **XSS**: React 默认转义(安全), 禁用 `dangerouslySetInnerHTML`(必须用时先白名单清洗如 DOMPurify); 富文本同理
- **CSRF**: SameSite cookie + 状态变更接口校验 Origin/Referer; 自定义 `Authorization` 头方案天然免疫
- **敏感信息**: 客户端代码不放任何密钥; `NEXT_PUBLIC_` 变量视为公开

## 密钥与隐私

- 密钥只在环境变量/密钥管理服务, `.env*` 在 `.gitignore`(只提交 `.env.example`)
- 若发现密钥曾提交: 立即作废轮换 + 用 git filter-repo 清除历史
- 用户数据合规: 明确收集最小化、用途告知、删除权; 日志与数据库脱敏

## 完成门禁

- [ ] OWASP 清单逐项核对完成, 有风险项已修复或记录缓解计划
- [ ] `npm audit` 无高危漏洞
- [ ] 密钥扫描干净, `.env*` 未入库
- [ ] 安全响应头与 CSP 配置生效
- [ ] 输出安全审查结果；高风险项需用户决策，否则继续进入阶段 7
- [ ] 检查框架、运行时和依赖的当前官方安全公告，不以过期年份标签代替核查
