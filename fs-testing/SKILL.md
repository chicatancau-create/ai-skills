# 测试规范 (fs-testing)

## 测试金字塔(投入比例)

```
        E2E(少, 关键路径)         ~10%
     集成测试(API/数据库)          ~30%
   单元/组件测试(细, 快)           ~60%
```

- 底层快而多, 顶层慢而少; 不在 E2E 里覆盖所有边界条件
- 每个新功能 = 代码 + 测试 + 通过, 缺一不可

## 单元测试(Vitest)

- 文件与源码同目录 `*.test.ts`, 命名描述行为: `calculateTotal.test.ts`
- 用 AAA 结构: Arrange(准备) → Act(执行) → Assert(断言)
- 纯函数/工具函数必须测; 边界值(空输入/零/负数/超长)必须覆盖
- **Mock 纪律**: 优先注入依赖而非 mock 内部实现; 只 mock 外部边界(网络/时间/文件)
- 测试间必须隔离(不共享可变状态), 不依赖执行顺序

## 组件测试(React Testing Library)

- **按用户视角查询**: `getByRole` > `getByLabelText` > `getByText` > `getByTestId`(最后手段)
- 断言行为(点击后出现了什么)而非实现(调用了哪个函数)
- 用 `userEvent` 模拟真实交互, 不用 `fireEvent`(除非必要)
- 表单组件: 测必填校验、错误提示、成功提交

## API/集成测试

- 测试真实路由+数据库(测试库), 不 mock 数据层
- 覆盖: 正常路径、参数校验(400)、未认证(401)、无权限(403)、不存在(404)、冲突(409)
- 每个测试事务回滚或清库隔离; 测试数据用工厂函数(如 faker)不用硬编码

## E2E 测试(Playwright)

- 只覆盖**关键用户旅程**(注册→登录→核心操作→退出), 每个旅程一个 spec
- 用 `data-testid` 或角色定位, 不用易碎的 CSS 选择器
- 网络请求可 mock(stub 外部服务), 内部接口走真实栈
- CI 中运行; 测试失败附截图/视频/trace

## 覆盖率与门禁

- 覆盖率统计(不含 mock/类型文件): 核心业务逻辑 ≥ 80%, UI 层 ≥ 60%
- 覆盖率是下限不是目标: 覆盖率高但断言弱 = 无效
- **TDD 实践**: 改 bug 先写复现测试(红) → 修复(绿) → 重构不破坏(保持绿)
- 每次提交前使用仓库包管理器运行测试并保持全绿; CI 必须跑测试, 失败阻止合并

## 完成门禁

- [ ] 新增功能均有对应测试(单元/组件/API/E2E 按金字塔分配)
- [ ] 错误场景测试齐全(非只测 happy path)
- [ ] E2E 覆盖核心用户旅程且 CI 可运行
- [ ] 覆盖率达标且无弱断言凑数
- [ ] 测试时长可控(单元秒级, 全套分钟级)
