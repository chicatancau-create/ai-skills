**规则**：每次工作运行都要默认走一遍对 `E:\本地AI使用手册`（见 [[reference-local-ai-manual]]）的读与写。

- **任务开始前（读）**：从 `首页.md` / `AI接入规则.md` 进，按**文件夹名**扫描判断属于
  `01-前端` / `02-后端` / `03-通用`，再用项目名、语言、框架、工具、错误信息、症状做全文检索，
  命中的记录当**候选经验**——当前项目代码、用户要求、安全规则优先于手册。
- **任务完成后（写）**：看有没有值得留的。只记**实际发生、可复现或有证据**的问题；
  没验证的进 `99-收件箱` 标 `needs-review`；验证过的按模板落到细分类目并改 `verified`、补分类 README 链接。
  不需要留就不写，别为了写而写。

**Why**：用户 2026-10-10 明确说这是"以后的铁律"，目的是不重复踩坑、让旧金点子可复用，
并把这套流程设成默认，而不是每次提醒。

**How to apply**：
- 结构铁律——**可以增量加文件夹和记录，不得重命名/删除/合并/大改现有顶层分类**；
  确实要大改时，报备必须含**原因、影响范围、候选方案、回滚方式**四要素，用户确认前不实施。
  不因一次记录就改长期分类，先进收件箱或 `99-待整理`。
- 写入前照 `90-模板` 的格式与命名规范；归档时要**同时**补该分类 `README.md` 和该板块 `*索引.md` 的链接
  （`AI接入规则.md` 只说 README，`README.md` 只说索引，两处都做才不漏）。改这两个文件的链接属正常归档，不算"大改"。
- 手册里的经验不能替代当前项目的复现、测试与代码审查；也不替代权限与安全策略。
- 注意：`E:\本地AI使用手册\AGENTS.md` 自我声明"只适用于该目录及子目录"，
  而用户 2026-10-10 的要求是**跨所有项目默认执行这套读/写流程**——以用户要求为准。
- **踩坑当场落册，不许只在对话里念叨**。2026-10-12 用户明确纠正："有坑那就写进手册啊，不要老是出声，老踩坑的"——
  我当时把"bash 吞 `$_`"当口头吐槽说了两遍却没写。判据：只要同一类失败**第二次**出现，
  就必须在本轮任务里按模板落一条 `踩坑-*` 记录（复现原文 + 最小修复 + 验证），而不是再复述一次感受。
- 与本条冲突的旧习惯（"只写 auto-memory 不写用户库"）以本条为准：两边都要落，
  auto-memory 给我自己跨会话用，手册给用户读。

- **库体检有现成工具，别再手写**：`03-通用/03-调试与验证/脚本-知识库wikilink完整性与孤儿检查-Obsidian.py`
  （2026-11-15 落册），查 DEAD / HASH / ORPHAN 三类，退出码 0=干净。跑法
  `python -X utf8 <该脚本> [vault根]`。用它之前先记住它已知的**三条例外**，否则会把假阳性当问题报给用户：
  ① 链接目标可以是 `.py`/图片等非 `.md` 附件；② 文件名里单个 `%` 合法（官方黑名单是 `%%` 不是 `%`）；
  ③ `03-通用/05-Codex工程知识库` 那个子库自己写明"不依赖 Obsidian、用表格+相对路径导航"，
  拿主库的 wikilink 入链规矩套它必然误报。
- **文件名里不要放 `#`**：Obsidian 官方把 `# | ^ : %% [[ ]]` 列为「不可靠用于链接的字符」且**不提供转义**，
  `[[名字#RRGGBB]]` 会被解析成"指向笔记《名字》的标题《RRGGBB》"而落空。2026-11-15 库里有 1 条这种死链，
  唯一正确修法是把文件改名去掉 `#` 再更新入链（改名属结构改动，先备份、报备、回滚方式齐全再做）。
