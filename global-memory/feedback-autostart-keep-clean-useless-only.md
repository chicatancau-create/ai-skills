**规则**：做后台清理时，**默认不动任何自启项**（Run 键、计划任务、服务启动类型）。只清"多余、没用的进程"：
更新器、遥测/面板常驻、按需才该拉起的 UI 进程、目标文件已不存在的死条目、残留 server（如 `adb`）。

**Why**：2026-11-03 我按「应用没开之前不该有它的进程」的思路，列了一大张「建议永久禁 / 暂时禁」的自启分级表，
用户直接否掉：**「你现在不需要管这个东西。因为我需要它开机自启，默认一直开着，所以你需要管的是那些多余、没有用的进程」**。
他要的是常驻便利，不是干净启动。

**How to apply**：
- 与 [[feedback-no-resident-process]] 不冲突：那条管的是**我交付的工具**默认别装自启；这条管**用户自己已有的应用**，他要一直自启。
- 判"没用的进程"用客观标准（见 [[reference-windows-autostart-process-audit]]），别拿"父进程已死"当依据。
- 杀之前先分类并给理由；**承载应用内核的服务/进程一律不杀**（Verge 的 mihomo 跑在 `clash_verge_service` 里就是典型）。
- 想省内存时优先杀更新器/遥测（本机实测一次清了约 190 MB，含 121 MB 的微信输入法更新器），
  并逐条回读 PID 证明确实杀掉了。
- 用户也接受「等下次重启后再复测自启行为」这种安排，不要为了验证反复重启他的机器。
