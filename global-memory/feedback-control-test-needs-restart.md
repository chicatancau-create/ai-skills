证明「某处代码改动导致了某个行为差异」时，**必须让对照组跑在一个新进程上**：改完/换回源文件后不重启服务，测出来的仍是旧进程的结论；共享内存状态的桩还要每轮重来。

**Why:** 2026-11-01 在鸿蒙课程服务端上做对照实验，连着两次自骗：
① 把 `middleware/auth.js` 换回未打补丁的原件后立刻跑断言，三条接口照样 PASS —— 因为后台那个 node 进程早把模块装进缓存了，换文件不等于换行为；
② 另一轮里同一进程被上一轮测试改过内存数据（用户名、avatar 已被写进桩），于是报出 7 个 FAIL，其中若干是状态残留而不是缺陷。
两种都会让我差点写下错误的结论，属于典型的「代理信号冒充证据」，见 [[feedback-rigor-audit]]。

**How to apply:**
- 顺序固定为：停服务 → 换文件 → **确认文件真的换了**（`grep -c` 关键行，让它在日志/输出里可见）→ 用**另一个端口**起新进程 → 跑断言 → 换回 → 再跑一次正向确认。
- 一开始就把**端口做成参数**（如 `CTR_PORT`），否则对照组和实验组抢同一端口，只能被迫复用同一个脏进程。
- 桩/fixture 若是内存态，每轮都要从原始种子重新加载；断言里别写依赖「某字段还是初始 NULL」这种会被上一轮污染的判断。
- Windows/git-bash 的具体坑：**没有 `pkill`**（用它杀后台服务会静默失败），后台服务用 TaskStop 停，停完 `netstat -ano | grep :PORT` 复探端口有没有被孤儿 node 进程占着（[[reference-qoder-taskstop-orphan-process]]）；
  带空格的可执行路径存进变量后必须整体加引号（`$N x.js` 会变成 `D:/DevEco` 找不到命令，[[reference-windows-python-encoding]]）。
