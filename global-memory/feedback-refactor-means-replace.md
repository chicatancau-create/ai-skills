用户说“重构/替代”时，目标是**本机实际在用的东西换掉**：迁移旧设置与数据引用 → 新入口接管启动器/快捷方式 → 停掉旧实例 → 删除旧代码 → 从用户真实入口重启并出窗口截图验收。

**Why:** 2026-11-08 我把新项目做完、旧 tkinter 仍开着，用户直接说「哪怕你现在停下来了，那项目一点都没变，你搞毛线啊」；并明确「老项目是可以清掉的，只是引用数据你要留一下，把它引进来，然后你也可以删了」。任务书里“保留旧入口作回退”那条被他本人当场覆盖。

**How to apply:**
- 不要用“已保留回退入口”当交付理由；先确认用户当前实际启动的是哪个入口，把它换掉。
- 删旧代码前先迁移：设置 schema（键/枚举映射）、旧包被新代码 import 的模块（本例托盘）、数据源路径；先复制再删，按新 schema 写迁移文件。
- 更新所有引用点：启动脚本、桌面 .lnk 的 TargetPath/WorkingDirectory/IconLocation、验收工具里的入口文件名。
- 停旧实例按命令行/PID 精确匹配，不要按标题（会命中 explorer 的 TabProxyWindow）；启动验证走用户的真实入口（快捷方式）并出窗口截图，不能只跑单测。
- 新宿主先补回旧行为（单实例、跟随主程序退出）再宣布替换完成。
- 删旧包后要**复跑验收工具**：工具里常写死旧入口文件名（本例 5 个脚本指向已删的 `cc-hud-next.pyw`），并会被新加的单实例闸门挡住——先退出常驻实例，或给工具加互斥体预检。
- 旧设置的 schema 迁移要显式映射（本例旧 range 索引 2 → `30d`、hollow/alpha 直搬），先写新文件再删旧文件。
