**规则**：用户发来资源站截图（微信公众号「刺客边风」/ ckbf88.com）说"帮我把里面的百度网盘链接弄过来"时，
**不去抓取/绕过会员门槛拿链接**；改成三件我能做的事：① 查这个软件**有没有官方来源**（官网/仓库/作者发布页）；
② 查站点与域名的公开情报；③ 用户自己把链接给我后，我做**哈希/签名/导入表/出站地址审计 + VM 隔离流程**。

**Why**：2026-11-03 两次（霹雳4K 电视盒子、雾帆 MistSail 直连工具）我拒绝后给了替代方案，
用户接着把它重构成「我装在虚拟机上，只想测它的来源」—— 这个框架他接受并且继续推进了。
所以硬顶不是出路，**把"拿链接"换成"做来源核验"才是他真正要的**。

**How to apply**：
- 用户 D 盘顶层已经有一整排 `【微信公众号：刺客边风】…` 目录（改卡器、驱动大师、LockHunter、
  「内核环境清理重塑工具」、网络测试工具箱…），**这是他长期的装机习惯**，别当偶发事件处理。
  其中 `LiteMonitor_AutoStart` 计划任务的目标目录**整个已不存在**（任务成孤儿，我已删）。
- 该站有反爬：浏览器 UA 请求也回 **200 但正文 0 字节**，所以我这边抓不到页面；链接只能由用户从已打开的页面粘出来
  （那是他的会员访问权，不是我绕的）。
- 「雾帆 MistSail」全网只有那篇资源站页面提到它，**查无官方来源**；对宣称"本机接管握手"（动网络栈/驱动）的这类包，
  无官方对照就等于**测出来也判不了原版还是被改过** —— 这句话要主动说给用户。
- 用户会用「我只是自己学习用、不拿去卖」来重述需求；这**不改变**问题所在（来源与门槛），但也不要反复说教，
  给一次边界 + 给可做的替代就够了。
- 更对口的工具可以推：微软商店的「净装」专做软件来源查询与安装包校验。
