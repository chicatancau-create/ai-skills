**位置**：`E:\本地AI使用手册`（用户 2026-10-10 建立）。定位是"本地运行的规则手册"：
所有踩过的坑和值得留下的做法都存这里，避免重复踩坑、复用金点子。

**入口与结构**（2026-10-10 实测目录树，改结构前先看这条）：

```
首页.md            总入口（按领域 / 按工作状态找）
AI接入规则.md      给 AI 的读回写流程（任务前 4 步、任务后 5 步、安全边界 3 条）
01-前端/           01-页面结构与HTML … 11-部署与兼容性、99-待整理、前端索引.md
02-后端/           01-架构与项目结构 … 11-第三方服务与集成、99-待整理、后端索引.md
03-通用/           01-需求理解与任务拆解 / 02-AI协作与提示词 / 03-调试与验证 /
                   04-工程规范与安全 / 99-待整理、通用索引.md
90-模板/           问题记录模板.md、验证记录模板.md、记录命名规范.md
99-收件箱/         收件箱.md（未验证材料的唯一容身处）
```

**记录规范要点**（照抄自库内文件，写之前按模板走）：

- 文件名 `问题类型-简短现象-技术关键词.md`；同一问题只留一条主记录，重复发现时在原记录补证据。
- frontmatter 含 `status: needs-review | verified | deprecated`；**未验证只能待在 `99-收件箱`**，
  完成复现+根因+最小修复+验证后才移到细分类目并改 `verified`。
- 每条至少写清：触发条件、实际现象、根因、修复、验证命令或操作、适用范围。
- 归档时要在**该分类的 `README.md`**（以及对应索引）补链接。
- 规则变化时新增记录、旧的标 `deprecated`，**不静默覆盖历史结论**。
- 安全边界：不写密码/Token/API Key/私钥/Cookie/个人隐私/生产敏感数据；手册内容不替代权限与安全策略。
