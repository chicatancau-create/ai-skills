在 CodeWeave（三合一重构）项目上，用户已给出**长期自主授权**：按工程文件（`docs/三合一重构总工程方案.md` 里程碑顺序与 `docs/数据库与资料库优化清单.md`）一步一步往下推，**不要再回来问「下一步做什么」**；提交、查看、修改、起停服务用于测试都直接做。

**Why**：用户说「后面的所有工作按照工程文件自动完成…不要再来问我该怎么做了。你需要提交也罢、查看也好、修改也好，都自动操作即可」，并在此前明确要求提速、用代理并行工作。他每天投入 6—10 小时独自推进这个竞赛项目，反复确认会打断他的节奏。

**How to apply**：
- 决策依据写在文件里：里程碑顺序、门禁命令、验收标准。遇到分叉先读方案与清单，再按「唯一权威源」「只标注不改写证据层」等自有规矩决定，然后动手并把理由记进执行记录。
- 仍然要停下来的情况：删除来源（旧根、旧库）、改变正式教学标准或核验状态、引入新外部依赖、对外发布/推送远端、任何要改写历史记录或教材正文的动作——这些先做非破坏性部分，把该决定单独列出等确认。实例（2026-09-20）：legacy-map 的 74 条 `pending → reviewed` 批量上调、以及复习偏移「三份口径不一致」（规则投影 `[0,1,3,7,14,30]` / 单元级 `null` / 客户端常量 `[1,3,7,14,30]`）该往哪边统一——都属于掌握标准与核验状态，不由整理动作代拍。
- 这类待决项要**做成决策就绪的摘要**交出去，而不是提问：条数、证据类型分布、影响面、回滚位置一次给全，并明确说我建议批哪一部分、哪一部分证据还不够。用户要的是不打断节奏，不是不被告知。
- **但「择优」类分叉不要列成清单让他选**。2026-09-20 在本项目交付总结里我列了 3 个待确认项 + 4 个候选功能，用户回：「后续的选择不要让我做了，你自己择优选择即可，我只需要成品。」→ 技术方向、下一步做什么、遗留物删不删这类**可逆的工程选择**，自己拍板、做完再报，最多在末尾用一句话说明我拍了哪些决定。真正需要停的只有上面那条里的破坏性/标准类动作。
- 互不重叠的工作派给并行子代理提速，每个代理给定文件边界、禁改清单与必须自证的命令退出码；它们的结果**自己复跑复核**，不采信转述。代理纠正了我的判断时如实写进记录。
- 每次交付都要有：真实改动、命令与退出码、回滚位置、诚实的未做清单。测试不许为了让它变绿而放宽断言。
- 起服务做验证是允许的（用户已授权在项目内自动启动）；结束时要停掉自己起的进程、清理临时目录，并且绝不动不属于自己记录的真实实例。
- 这个授权模式**不限于 CodeWeave**：2026-09-20 在本地模型部署排障（D:\Models）上，用户同样说「后续你一直测试，直到成功为止。我有事做，全权放给你处理」，然后长时间离开。碰到「一直试到成功」这类指令时，要把整条链路自己跑完（定位根因 → 改配置 → 重启验证 → 实测数据 → 回写交接文档），中途不要留「等你确认」的半成品。
- **风险动作单独问一次就会拿到授权，不要因为有自主授权就擅自做、也不要因此干脆不做**。同一天我把「要不要替换第三方应用自带的 exe（llama-server 包装脚本）」写进文档等点头，用户回来直接回「授权试试那个启动丢参数的包装脚本」。⇒ 做法是对的：先把风险和回滚讲清楚，再单独要一次授权；被授权后就完整做完并实测。
- **偏好类分叉可以问，技术择优不要问**。上面第 16 条说的是工程选择自己拍板；但「模型显示名叫什么」「改名要不要连 API id 一起改」这种属于用户个人偏好，用 AskUserQuestion 一次问清（含具体候选名与影响面）他答得很爽快，没有嫌烦。
- 自主授权**不覆盖**：把密钥/凭据整段贴进对话（本机 token-router 的 key 只给文件路径和行号让他自己复制）、以及删除他自己动过手的东西（他把聊天模型切成 Qwen 后又改回来，只说明我改了什么、并问要不要定回去）。
- **2026-09-22 在一个 Python 采集工程上再次确认同一模式**：用户说「后续我不在这边，没有空给你授权。我现在给你全部的权限，你直接一次性把那个工程文件全部做完。当然要一步一步地做，火力全开地去做」。⇒ 面对里程碑总方案这类文档，按其顺序一路做到底、每步提交、不要中途要授权；但**里程碑门禁里要求真人账号/平台侧操作的部分（真人账号登录、平台侧操作）不能替他伪造**——把可自动化的部分做完，并留下他回来几分钟就能跑完的取证脚手架。

- **【2026-11-07 本机新流程，覆盖上面的「一路做到底」】**：用户因本地模型额度扛不住，把节奏改成**每轮只做一个明确任务块 → commit 并双推 GitHub + AtomGit（`domestic`）→ 停下交回网页端 AI 规划与审核 → 由他给下一步指示**。所以在这台机器上，「自主执行」现在只在**单轮范围内**成立：本轮动手、验证、双推，推完即停，不要自行连跑多轮或反过来问「下一步做什么」以外的东西。每轮收尾细则见 [[feedback-round-then-push-both-remotes]]。

- **2026-11-07 cc-hud 重构的边界**：用户说"遇到阻碍按你认为最合理的方式继续、不要停下来"时，缺执行文档可以先问一次；
  拿不到就按现有代码与本机数据格式重建，并在文件头**标注"重建版"**、在交付里说明偏离。反过来，任务里写死
  "不 commit/push/merge"时，覆盖本机默认的每轮双推流程 —— 任务级显式禁令优先。

- **【2026-11-08 资料库收尾再次放宽】**：用户说「后面的操作，你不要问我允不允许啊，你直接看情况自己通过。你认为合理且不会对本机器这个项目造成影响的话，直接通过就行」。⇒ 可逆、局部、无外部副作用的操作（文档修订、测试、构建、提交推送、临时服务）直接做；只有真正破坏性/不可逆、公开暴露敏感内容、动凭据或改写学习验收标准时才停下说明，而不是逐项征求许可。
