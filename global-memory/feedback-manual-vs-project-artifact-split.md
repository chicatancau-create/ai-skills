写 `E:\本地AI使用手册` 的记录时，**正文按通用经验写，项目专有的东西只放在可整段删掉的位置**
（主要是末尾「关联」里的代码路径、以及证据片段中的应用名）。

**Why**：2026-10-14 那次会话被用户整体废弃、要求删除全部产物。问到手册怎么处理时，
选的是「留通用经验，抹掉项目痕迹」而不是全回退。也就是说手册的价值判定与项目成败**解耦**——
项目黄了，从中学到的 Windows/MSVC/PowerShell 坑仍然算资产。如果当时把结论和项目路径混写在一起，
就只能二选一：要么连带删掉有用的经验，要么留下指向已删除目录的死链接。

**How to apply**：
- 记录正文里**不要**出现项目名、仓库路径、进程名；证据片段用 `<被测应用>` 这类占位符。
- 「相关代码」一行写具体路径没问题（那是唯一需要抹的位置），但要**同时把可复现的最小修复形式抄进正文代码块**，
  这样源工程删了记录仍自足。
- 被废弃时：删掉路径行、把占位符替换到位即可，不要整条删除。
- 反过来，纯项目上下文（边界、目录分工、里程碑）走 project memory，**不要**写进手册。
