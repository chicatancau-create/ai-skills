用户给**编号清单 + 「其他的一切东西都不要动」**这类措辞时，就只做清单内的条目；
如果之前几轮我多加过不在清单里的东西，**交付时要单独点出来并问要不要撤**，不能当作既成事实混进去。

**Why**：2026-11-04 做 uni-app 课程作业时，上一轮我在没人要求的情况下给 `pages.json` 多加了
`borderStyle` 和 `backgroundColor` 两行（虽然等于框架默认值、视觉零变化）。
下一轮用户直接立规矩：「你只需要按照最低要求帮我改完以下几点，**其他的一切东西都不要动**」，
并给了三条明确条目（加默认色/选中色、选中图标改蓝、同学页加占位图+哭表情）。
他要的是**作业能对着评分点、改动面可控**，不是"顺手更好"。

**How to apply**：
- 收到编号清单 → 逐条实现，逐条给实测证据；**不夹带**重构、格式化、加默认值、"顺便清理"。
- 已经多加过的：在收尾里单列一段「有一件要你点头我才动」，说明它是否影响外观/行为，并给撤除方案。
- 用户自己并行改过文件时（我看到 `selectedColor` 已被他改成 `#1296db`），**保留他的值不覆盖**，
  只补缺失项；写脚本时按现状匹配，匹配不上就**停手报错而不是猜**（那次断言正好拦住了我基于旧形状的替换）。
- 课程/作业类任务的判据是"对着要求清单能不能过关"，不是工程质量最优；
  主动指出清单里没写但明显是笔误的地方（如启动页顺序、tab 文案），**提问而不是动手**。
