**不要往 C 盘放任何东西 —— 包括中间产物。** 用户没另行指定位置时，「工作区」就是默认落点；批量下载、解压暂存、一次性脚本都建在工作区里（如 `<工作区>\05-外部资料库\_采集暂存\`），用完自己清掉。

**Why:** 2026-11-04 我在 `C:\Users\Admin\AppData\Local\Temp\` 下建了 `gh_measure`/`gh_dl`/`gh_probe` 三个暂存目录，准备把 55 个 GitHub 仓库的采集包先落 C 盘再整理进库。用户当场打断：「你东西不要搞进C盘，一般数据最终落地的话，只能放进我指定的位置……一般情况下，我没说放其他地方，就是放工作区」。这和 [[feedback-install-to-d-drive]]（软件禁装 C:）是同一条诉求的两面：C 盘是系统盘，不是他的存储区，而且他要在 Obsidian 里看得见、能交给别人调用，藏在 Temp 里的东西对他等于不存在。

**How to apply:**
- 开工前先定「最终落点在工作区的哪个目录」，中间产物也建在那下面的 `_`-前缀暂存子目录里，别图省事用 `%TEMP%`。
- 暂存目录是本轮我自己的产物，抽取完成后逐项删掉（见 [[feedback-destructive-file-ops]]：只删本任务产物），别把压缩包留在库里。
- 已经写错位置时的补救顺序：先在工作区建好新目录并复制过去 → 再删 C 盘原件 → 报出「C 盘剩余 X 项 = 0」和回收体积，让用户看到结果而不只是听到承诺。
- 这条推翻了 [[toolkit-is-tools-only]] 和 [[qoder-artifact-locations]] 里旧的「中间件放 %TEMP%」建议 —— 那两条已同步更正。
- 例外：Qoder 应用自己写的 `C:\Users\Admin\.qoder\...` 运行时目录不属于「我放的东西」，不要去动。
