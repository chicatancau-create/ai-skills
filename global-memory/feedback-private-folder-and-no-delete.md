处理用户的浏览器书签/收藏时，四条硬规则：

1. **`绅士` 目录不碰**：不打开、不枚举子项、不打印内容、不参与扫描与重排。需要它出现在导出文件里时，
   **整棵子树原样搬运**（URL 一字不改），并在事后用集合交集证明"零混入其它目录 + 零条数丢失"，
   且这个证明过程本身也不得打印该目录的内容。用户会反复强调这条（本次强调了两遍）。
   **Why:** 明确划出的隐私边界，且他不想看到我为此反问。
2. **不删任何东西，哪怕他说了"可以直接删除"**：把失效项移进一个
   `疑似失效（待你定夺）` 大目录（可再分"你已确认无救" / "本轮新发现"），并在报告里逐条列出。
   **Why:** 他的总规则是"所有内容不能删除，但可以移动整理"；删与不删他要自己判断。
   **How to apply:** 交付文件里条目数必须 ≥ 原始条目数，用"缺失 0"这类计数自证。
3. **每条结论标证据来源**：`已进页面看过` / `正文确认` / `正文·标题纠正` / `URL 结构` / `沿用原目录` /
   `证据不足`。抓不到正文就写抓不到，绝不把推断写成观察。
   **Why:** 他要求"仔仔细细确定这东西到底干嘛的"，同时会核对我的措辞。
4. **授权即离场**：他会说"我给你权限你自己去处理""我后面没有空"，然后不再回复。
   此时不要停下来问；遇到"能不能做到"的分叉，用**一次有界、可回滚的探针实验**自己判定
   （例：改 Chrome 书签库前先加一个测试目录看它采不采纳），拿到否定证据就如实说做不到并给两下点击的方案。
   **Why:** 他讨厌被反复确认打断，但更讨厌我假装完成。

**分类口径**：他要"大套小、小还能再套小，但别特别抽象或特别细"，无法归类的进 `待归类`。
默认**保留他原目录表达的意图**，只对他目录与页面内容矛盾的条目做定点纠正 —— 我试过让关键词规则全权
分类，结果"函数"把 Excel 拖进数学、"教程"把 Java 课拖进故障排查，反而制造新错误。
