# 性能优化 (fs-performance)

## 核心指标(Core Web Vitals)

| 指标 | 目标 | 含义 |
| --- | --- | --- |
指标阈值以当前 web.dev 官方 Core Web Vitals 文档为准；项目应在 `docs` 或 CI 中记录核对日期、设备/网络条件和预算，不把历史阈值永久写死。

## 铁律: 先测量, 后优化

1. 用 Lighthouse / PageSpeed Insights 建基线数据
2. 定位瓶颈(网络? JS? 渲染? 后端?)再动手
3. 每项优化前后对比指标, 无提升的优化不做
4. 不迷信工具建议, 结合场景判断

## 前端优化清单

### 渲染策略(Next.js)
- 静态内容 SSG/ISR, 动态内容 SSR + 缓存, 交互密集区客户端渲染
- 正确选择: 首页/营销页静态化; 列表页 ISR + `revalidate`; 个性化数据按需客户端获取

### 资源
- [ ] 图片一律 `next/image`(懒加载、尺寸预占防 CLS、AVIF/WebP 自适应)
- [ ] 字体 `next/font`(自动子集、无布局偏移、无阻塞)
- [ ] 第三方脚本 `next/script` 懒加载/延迟加载(如统计、客服)
- [ ] 视频不自动播, 首屏无大视频

### Bundle
- 用 `@next/bundle-analyzer` 分析, 大依赖按需引入
- 重组件 `dynamic(() => import(...))` 按需加载(图表、编辑器、地图)
- 工具库用 tree-shaking 友好的导入方式(不用 `import * as _`)

### 运行时
- 列表渲染: 长列表虚拟滚动, `key` 稳定唯一
- 避免渲染中创建新对象/函数传给 memo 组件(用 useCallback/useMemo 有意义时)
- 防抖/节流输入类事件; 不阻塞主线程(长任务拆分)

### 缓存
- 静态资源加长缓存 + 内容哈希文件名
- GET 接口配 `Cache-Control`/CDN 缓存; 变更用 revalidate 失效

## 后端优化清单

- [ ] 慢接口打点(耗时/慢查询日志), 先找最慢的 20%
- [ ] 数据库: 索引命中(`EXPLAIN ANALYZE`)、批量查询替代循环、减少返回字段
- [ ] 热点数据缓存(内存/Redis), 注意失效策略(缓存穿透/雪崩)
- [ ] 连接池合理配置, 避免连接泄漏
- [ ] 长任务异步化(队列), 接口快速返回 202
- [ ] 响应压缩(gzip/brotli)

## 性能预算

- 定义预算并写入 CI(如 Lighthouse CI): 依据目标用户、设备和当前官方指标设定，并记录测量条件
- 超出预算视为构建失败, 阻止性能回退

## 完成门禁

- [ ] Lighthouse 全指标达标(桌面+移动)
- [ ] bundle 分析无异常大依赖
- [ ] 后端慢接口 TOP 问题修复并复测
- [ ] 性能预算配置进 CI
