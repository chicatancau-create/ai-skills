# 代码审查与质量门禁 (fs-code-review)

## 提交前自检(每次提交前执行)

1. 使用仓库声明的包管理器运行 `lint`、`typecheck`、`format`、`test` 并确保全绿
2. 自查 diff: 有没有调试代码(`console.log`/注释掉的代码/临时文件)
3. 自查命名: 变量/函数名是否表意(不靠注释解释名字)
4. 确认无密钥/敏感信息混入
5. 提交信息符合 Conventional Commits, 描述"为什么"不只"是什么"

## 审查关注点(优先级从高到低)

1. **正确性**: 边界条件、错误路径、并发、空值处理
2. **安全**: 输入校验、权限、注入(对照 fs-security)
3. **设计**: 职责单一、模块边界、依赖方向
4. **可读性**: 命名、结构、复杂度
5. **一致性**: 与现有代码风格统一
6. 最后才看: 格式(交给工具)、风格偏好(不纠缠)

## 代码质量标准

- **命名**: 动词开头的函数(`getUserById`)、名词的名词短语变量(`userList` 而不是 `data`)、布尔 `is/has/can` 前缀; 不用无意义缩写
- **函数**: 单一职责, ≤50 行为宜; 参数 ≤4 个(多则用对象参数)
- **复杂度**: 嵌套 ≤3 层, 提前 return 减少 else; 三元仅用于简单场景
- **类型**: TypeScript strict; 禁止 `any`(确需时 `unknown` + 收窄, 并注释原因); 不用类型断言硬掰(`as unknown as X` 是红灯)
- **魔法值**: 有业务含义的数字/字符串提取为命名常量
- **重复代码**: 3 次复制才抽象(rule of three); 不为了 DRY 提前过度抽象
- **注释**: 写"为什么"(决策、坑), 不写"是什么"(代码自己会说); 删除注释掉的旧代码
- **错误处理**: 不吞异常不空 catch; 用户可见错误友好化, 系统错误记日志

## 重构原则

- 无测试不重构: 重构前先保证测试覆盖
- 小步走: 每次重构行为不变, 测试保持绿
- 坏味道优先级: 重复代码 > 长函数 > 大类 > 长参数表 > 数据泥团

## 门禁配置

- CI 强制: lint + typecheck + test 失败阻断合并
- 本地 hooks: 按仓库选定的 hooks 工具运行 lint-staged/格式化与提交格式校验
- PR 模板: 变更说明 / 测试情况 / 截图(UI 变更)/ 关联 issue

## Git 规范

- 分支: `feat/xxx`、`fix/xxx`、`docs/xxx`; 小步提交, 一提交一事
- 提交信息: `feat: 用户列表支持搜索` / `fix: 修复空状态下分页崩溃` / `refactor: 抽取订单金额计算`; body 写原因与取舍
- 不提交: 依赖锁文件以外的大文件、构建产物、密钥
